# Око МЧС: сервер + панель мониторинга

FastAPI + SQLAlchemy + PostgreSQL/SQLite. Принимает данные от дрона (телеметрия, найденные ЧС с фото),
хранит их и отдаёт панели мониторинга (React + Leaflet на настоящей карте).

## Что внутри

- `app/` — серверная часть: приём данных от дрона, слияние дублей, авторизация, разграничение ролей.
- `frontend/` — панель мониторинга (React + TypeScript + Vite + Leaflet). Собранная версия — `frontend/dist`.
- `fake_drone.py` — имитация дрона: пролетает маршрут и шлёт телеметрию + находки, как будет делать Webots.
- `drone_client_example.py` — функции отправки для контроллера Webots (копировать в `drone_patrol.py`).
- `tests/` — тесты логики и API (включая роли и авторизацию).

## Типы ЧС и роли

Типы: `fire` (пожар), `flood` (наводнение), `pollution` (загрязнение), `landslide` (оползень) —
детектор может слать и русские слова (пожар, вода, утечка, оползень...). Тип `person` убран:
дрон не отличает пострадавшего от прохожего, поэтому люди — это поле `people_count`
(«людей в зоне очага»), а не отдельный тип.

Степень: `low` / `medium` / `high` (низкая / средняя / высокая). Статус ЧС: `new` / `confirmed` / `closed`.

Роли (видят только «свои» типы ЧС — фильтрация на сервере):

| Логин | Пароль | Роль | Видит |
|---|---|---|---|
| `operator` | `operator123` | оператор ЦУКС | всё + меняет статусы |
| `fire` | `fire123` | пожарная служба | пожары, наводнения, оползни |
| `eco` | `eco123` | экологическая служба | загрязнения |
| `viewer` | `viewer123` | наблюдатель | всё, только чтение |

Дрон аутентифицируется ключом `X-API-Key` (переменная `DRONE_API_KEY`, по умолчанию `oko-drone-key`),
люди — JWT через `POST /api/login`.

## Запуск

### Вариант 1. Docker (PostgreSQL, как на схеме проекта)
```
docker compose up --build
docker compose exec api python -m app.seed --reset     # демо-данные (по желанию)
```
API: http://localhost:8000  ·  панель: http://localhost:8000/  ·  документация: http://localhost:8000/docs

### Вариант 2. Без Docker (SQLite, для быстрой проверки)
```
pip install -r requirements.txt
python -m app.seed --reset
uvicorn app.main:app --reload
```
Если `frontend/dist` собран, панель откроется прямо на http://localhost:8000/ (сервер отдаёт её сам).

### Собрать панель из исходников (нужны Node.js и npm)
```
cd frontend
npm install
npm run build        # результат -> frontend/dist
```
Для разработки: `npm run dev` (порт 5173, /api и /media проксируются на :8000).

### Имитация дрона (проверка end-to-end)
Сервер должен работать. Во время полёта открывайте панель — данные приходят в реальном времени.
```
python fake_drone.py              # один вылет, со сценой как в Webots
python fake_drone.py --speed 4 --loops 3
```

### Тесты
```
pytest
```

## База данных
| Таблица | Содержимое |
|---|---|
| `drones` | дроны |
| `users` | операторы/службы: логин, хэш пароля (PBKDF2), роль |
| `missions` | вылеты: дрон, начало, конец, статус `active` / `finished` |
| `telemetry` | положение дрона во времени: `x, y, z`, курс, заряд, состояние |
| `incidents` | ЧС: тип, степень, статус, координаты, площадь, кадры, люди в зоне, подтип, фото |

Фото хранятся файлами в `media/incidents/`, в базе только путь. Таблицы создаются автоматически при запуске
(миграций нет, для хакатона это не нужно). Чтобы всё сбросить: `python -m app.seed --reset`.

## Контракт данных
Координаты `x, y` в метрах симулятора (x на восток, y на север, начало в точке старта).
В ответах API сразу приходят `lat`/`lon` для карты: они считаются от базовой точки
`BASE_LAT` / `BASE_LON` (по умолчанию Екатеринбург, задаётся переменными окружения).
Время везде в UTC с явным часовым поясом.

## Эндпоинты
| Метод | Адрес | Кто | Что делает |
|---|---|---|---|
| GET | `/api/health` | все | проверка |
| POST | `/api/login` | все | вход `{username, password}` -> `{token, user}` |
| GET | `/api/me` | Bearer | текущий пользователь и его допустимые типы ЧС |
| GET | `/api/drones` | Bearer | список дронов |
| GET | `/api/drones/{id}/position` | Bearer | последнее положение дрона |
| GET | `/api/missions` | Bearer | список вылетов |
| POST | `/api/missions` | оператор (JWT) или дрон (ключ) | начать вылет `{"drone_id": 1}` |
| POST | `/api/missions/{id}/finish` | оператор или дрон | завершить вылет |
| GET | `/api/missions/{id}/track` | Bearer | весь путь дрона (линия на карте) |
| POST | `/api/telemetry` | дрон (ключ) | положение дрона `{mission_id, x, y, z, yaw?, battery?, state?}` |
| POST | `/api/incidents` | дрон (ключ) | сообщить о ЧС (`multipart/form-data`: `mission_id, type, severity, x, y, area_pct`, необязательно `people_count, subtype, note`, фото `image`) |
| GET | `/api/incidents` | Bearer | список ЧС (только типы роли). Фильтры: `mission_id`, `type`, `severity`, `status`, `limit` |
| GET | `/api/incidents/{id}` | Bearer | одна ЧС |
| PATCH | `/api/incidents/{id}` | оператор | меняет `status` и `note` |
| GET | `/api/stats` | Bearer | сводка по типам/степеням/статусам (только видимые роли ЧС) |
| GET | `/media/...` | все | фотографии (поле `image_url` в ЧС) |

**Защита от дублей.** Если дрон шлёт очаг того же типа ближе 4 м (`MERGE_RADIUS_M`) к уже известному
в этой миссии, сервер не создаёт новую запись: он обновляет старую (счётчик `detections`, максимальная
степень, максимум людей в зоне, самое крупное фото, усреднённое положение) и отвечает кодом 200
с `"merged": true`. Новая ЧС возвращается с кодом 201.

## Панель мониторинга (React + Leaflet)

- карта арены (Leaflet, CRS.Simple): снимок полигона строго сверху из Webots (`frontend/public/arena.jpg`),
  координаты в метрах симулятора кладутся на снимок напрямую, без lat/lon и спутниковых тайлов.
  Привязка настраивается в `frontend/src/IncidentMap.tsx` (размер пола, центр, ориентация);
- маркеры ЧС по типам с кольцом степени опасности, пульсация у высокой;
- фильтры по степени (со счётчиками) и по типу, лента ЧС по убыванию опасности;
- карточка ЧС: фото с дрона, «людей в зоне очага», подтип, площадь, статус; оператор меняет статус и пишет заметку;
- тосты о высокой степени (новый очаг или эскалация), клик по тосту открывает очаг;
- маркер дрона с зарядом и трек активного вылета; опрос API раз в 2 с;
- вход по ролям: служба физически не получает чужие типы ЧС (сервер отдаёт 403).

## Как подключить дрона
Готовые функции отправки лежат в `drone_client_example.py`. В контроллере Webots вызывайте их с короткими
таймаутами (они уже в `try/except`), чтобы связь с сервером не тормозила полёт. Не забудьте заголовок
`X-API-Key` — он обязателен для `/api/telemetry`, `/api/incidents` и старта/финиша вылета.

## Переменные окружения
`DATABASE_URL`, `MEDIA_DIR`, `BASE_LAT`, `BASE_LON`, `MERGE_RADIUS_M`, `MAX_IMAGE_BYTES`, `CORS_ORIGINS`,
`DRONE_API_KEY`, `SECRET_KEY` (секрет подписи JWT — в проде задать обязательно!), `TOKEN_TTL_HOURS`,
`FRONTEND_DIR` (по умолчанию `frontend/dist` рядом с бэкендом).
