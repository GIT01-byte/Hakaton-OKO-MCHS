# 🚁 Око МЧС: Автономный мониторинг ЧС

Комплексный проект для хакатона, состоящий из **автономного контроллера дрона** (Webots) и **серверной части с панелью мониторинга** (FastAPI + React).
Дрон автономно патрулирует территорию, распознает чрезвычайные ситуации (пожары, наводнения, свалки, оползни, людей) с помощью компьютерного зрения, и передает данные в реальном времени в штаб на интерактивную карту.

## 🚀 Запуск проекта

### 1. Запуск сервера (Бэкенд + БД)

Убедитесь, что у вас установлен Docker Desktop.

```bash
cd oko-backend
docker compose up --build
```

- API (Swagger): http://localhost:8000/docs
- Панель мониторинга: http://localhost:8000/
- (Опционально) Заполнить БД демо-данными:
  ```bash
  docker compose exec api python -m app.seed --reset
  ```

**Тестовые аккаунты для панели:**

- `operator` / `operator123` — Оператор ЦУКС (видит всё, меняет статусы).
- `fire` / `fire123` — Пожарная служба (пожары, наводнения).
- `eco` / `eco123` — Экологи (загрязнения).
- `viewer` / `viewer123` — Наблюдатель (только чтение).

### 2. Запуск дрона в Webots (Windows PowerShell)

Откройте симуляцию Webots с моделью Mavic 2 Pro.
Для запуска контроллера в отдельном терминале PowerShell используйте следующий скрипт (он настраивает переменные окружения для связи по TCP):

```powershell
$env:WEBOTS_HOME = "C:\Program Files\Webots"
$env:PATH = "$env:WEBOTS_HOME\lib\controller;$env:WEBOTS_HOME\msys64\mingw64\bin;$env:PATH"
$env:PYTHONPATH = "$env:WEBOTS_HOME\lib\controller\python"

# Запуск контроллера
webots-controller --protocol=tcp --ip-address=127.0.0.1 ./src/main.py
```

_Примечание: Дрон подключится к серверу по адресу `http://127.0.0.1:8000/api` (настраивается в `logger.py` или переменной `OKO_API_URL`)._

## 🧠 Как это работает

### Контроллер дрона (`src/`)

1.  **Взлет и патруль:** Дрон поднимается на высоту и летит по квадратам (`fsm.py`).
2.  **Компьютерное зрение (`vision.py`):** Параллельно работает YOLO (люди, животные, мусор) и классический CV (HSV-маски для огня и воды).
3.  **Геопривязка (`geo.py`):** Каждый найденный объект проецируется с кадра камеры на плоскость земли (z=0) с учетом высоты, крена и тангажа.
4.  **Облет препятствий (`avoidance.py`):** Оптический поток (Farneback) предотвращает столкновения с деревьями.
5.  **Отправка (`logger.py` + `drone_api.py`):** Данные пишутся локально в `telemetry_log.csv` и `mission_reports.json`, а затем асинхронно отправляются на сервер (в отдельном потоке, чтобы не тормозить полет).

### Сервер (`oko-backend/`)

- Принимает телеметрию (`POST /api/telemetry`) и инциденты с фото (`POST /api/incidents`).
- **Защита от дублей:** Если дрон шлет очаг того же типа ближе 4 метров, сервер обновляет существующую запись, а не создает новую.
- **Панель (React):** Карта на базе `Leaflet` использует `CRS.Simple` и накладывает координаты на реальный скриншот полигона (`arena.jpg`), позволяя видеть дрон и очаги возгораний в реальном времени.

## 🔌 Основные Эндпоинты API

| Метод   | Эндпоинт              | Доступ         | Описание                                            |
| ------- | --------------------- | -------------- | --------------------------------------------------- |
| `POST`  | `/api/telemetry`      | Дрон (API-Key) | Отправка координат (X, Y, Z, Yaw) и данных CV       |
| `POST`  | `/api/incidents`      | Дрон (API-Key) | Отправка факта ЧС (multipart/form-data с фото)      |
| `POST`  | `/api/login`          | Все            | Авторизация и получение JWT-токена                  |
| `GET`   | `/api/incidents`      | JWT            | Получение списка ЧС (с фильтрацией по ролям)        |
| `PATCH` | `/api/incidents/{id}` | Оператор       | Изменение статуса ЧС (`new`, `confirmed`, `closed`) |
| `GET`   | `/api/stats`          | JWT            | Статистика по типам и степеням опасности            |

## ⚙️ Переменные окружения (Дрон)

Вы можете настроить параметры связи в `logger.py` или через окружение:

- `OKO_API_URL` — адрес сервера (по умолчанию `http://127.0.0.1:8000/api`).
- `OKO_API_KEY` — ключ дрона (по умолчанию `oko-drone-key`).
- `TELEMETRY_INTERVAL` — частота отправки телеметрии в секундах (в `config.py`, рекомендуется `0.5`).
